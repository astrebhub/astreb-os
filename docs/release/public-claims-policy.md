# Public Claims Policy: ASTREB / JAZEKKER v0.3

Date: 2026-05-27
Scope: claims allowed for the read-only governed production preview path

## Allowed Claims

The project may be described as:

- locally implemented;
- locally tested;
- governed prototype;
- controlled runtime;
- security baseline implemented locally;
- read-only production-preview candidate;
- human-approved governance architecture;
- system with controlled execution boundaries;
- orientation infrastructure prototype.

Preferred wording:

```text
Locally implemented and tested governed AI orientation prototype with
controlled execution boundaries and security-baseline governance controls.
```

## Conditional Claims

| Claim | Required Evidence |
| --- | --- |
| Published review snapshot | Branch and commit URL. |
| CI validated | Passing GitHub Actions run for the exact commit. |
| Production preview deployed | Deployment URL, HTTPS, secrets review, CI pass and release approval. |
| Audit-ready | Durable append-only audit storage and access-control review. |
| External execution capable | Separate ASTI release gate and human approval evidence. |

## Prohibited Claims Without Further Verification

Do not claim:

- production deployment;
- autonomous AI governance;
- self-improving runtime;
- deployed civic infrastructure;
- autonomous execution platform;
- autonomous publishing;
- live Telegram/WhatsApp/email execution;
- irreversible self-modification;
- production-grade security;
- production-grade audit immutability.

## Required Disclaimers

For investor, architect or pilot communication:

- The current state is not a production deployment.
- External execution is disabled.
- META-QMS proposes improvements but does not apply them.
- Human approval remains required for sensitive decisions and all external
  action gates.
- The published branch is review evidence, not product release approval.

## Correction Procedure

If an overclaim is made:

1. Correct the source text.
2. Record the correction in governance notes.
3. If public, publish a clarifying update.
4. Add the claim pattern to this policy if recurring.
